# Allreva Development Flow

이 Skill은 모든 작업을 강제하지 않는다. 한 파일의 명확한 수정처럼 작은 작업에는 사용하지 않는다.

## 1. 시작 전 확인

현재 프로젝트의 `AGENTS.md`를 읽고, 아래를 짧게 확인한다.

- 작업의 완료 조건
- 관련 코드와 문서 경로
- Issue, RFC, ADR이 필요한지
- 현재 worktree와 테스트 명령

사람용 규칙은 `Allreva_Docs`를 기준으로 한다. 탐색 경로는 현재 프로젝트의 `AGENTS.md`를 따른다.

## 2. 역할 선택

다음에만 읽기 전용 subagent를 사용한다.

| 상황 | 역할 |
| --- | --- |
| 영향 범위가 여러 모듈·문서에 걸침 | `scout` |
| 구현 뒤 요구사항·검증 누락을 확인해야 함 | `reviewer` |

- 단순 작업에는 main session이 직접 처리한다.
- 같은 worktree를 고치는 writer는 하나만 둔다.
- 사용자 결정이 필요한 설계 선택은 subagent에게 맡기지 않는다.

## 3. 컨텍스트 계약

subagent에는 전체 대화 대신 아래만 전달한다.

```text
목적:
확인할 경로 또는 질문:
완료 조건:
제외 범위:
```

결과는 아래 형식으로 제한한다.

```text
결론: 1~3문장
근거: 파일 경로와 핵심 행위
위험 또는 미확인 항목: 최대 3개
다음 단계: 하나
```

## 4. 구현과 마무리

1. main session이 탐색 결과를 바탕으로 짧은 계획을 확정한다.
2. writer가 구현과 프로젝트 검증을 수행한다.
3. 필요하면 `reviewer`가 diff와 완료 조건만 보고 누락을 점검한다.
4. Issue, RFC, ADR, PR에는 최종 판단과 결과만 남긴다.

Git 도구 사용 규칙은 별도 도입 전까지 현재 프로젝트의 `AGENTS.md`와 CI 규칙을 따른다.
